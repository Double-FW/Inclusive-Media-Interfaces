# Agent Guidance: Inclusive Media Interfaces

## Purpose and authority

Use this repository for design, research, and review of interfaces through which people discover, configure, navigate, and control audiovisual media and access services. Follow the repository README and keep interface guidance separate from content production, caption authoring, legal assessment, and general multimodal principles.

An agent may summarize and apply the repository's guidance. It must not claim that a device, platform, programme, service, or operator is legally compliant without appropriate evidence and human authority.

## Required context

Before giving a specific recommendation, identify or request:

- service and interface type;
- device, player, remote, and relevant software version where known;
- task and user goal;
- viewing/listening environment and relevant constraints;
- media version and access services available;
- whether the question concerns interface discovery/control, media production, a caption file, or regulatory evidence.

Do not invent missing details. Label assumptions and identify what must be checked.

## Review method

For each relevant journey, consider:

1. Discovery: Can the person find the content, access service, and relevant setting?
2. Setup: Can they configure the device or service without relying on an unavailable mode or undocumented sequence?
3. Control: Can they operate playback, navigation, volume, captions, subtitles, audio description, and other available options using suitable input methods?
4. State: Is the current mode, selection, focus, playback state, and consequence clear?
5. Continuity: Do settings and context behave as expected across content, sessions, and devices? Do not assume a preference should persist without evidence or user control.
6. Recovery: Can the person pause, resume, correct, exit, and recover from errors or interruptions?
7. Environment: Consider distance, lighting, noise, fatigue, time pressure, shared viewing, and other relevant context without assuming these affect every person equally.
8. Evidence: Distinguish source-based guidance, actual user evidence, technical inspection, inference, and untested recommendations.

## Scope routing

- For the semantics and general input/output modality framework, use **Inclusive Multimodal UX**.
- For media production workflows and accessible content creation, use [Accessible Film, TV and Video Content Production Management](https://github.com/Double-FW/Accessible-Film-TV-and-Video-Content-Production-Management).
- For caption or subtitle authoring and technical delivery, use [Closed Caption Subtitles](https://github.com/Double-FW/Closed-Caption-Subtitles).
- For regulatory scope, duties, or evidence, use [AVMSD](https://github.com/Double-FW/The-Audiovisual-Media-Services-Directive-AVMSD-) and the applicable legal specialist. Do not treat this repository as legal advice.
- For game-specific interaction, use [Inclusive Games Design](https://github.com/Double-FW/Inclusive-Games-Design).

Do not duplicate a full guide from a related repository. State which source controls when guidance overlaps, and link to it.

## Source, evidence, and maintenance

- Read the relevant source and record its path and version before making claims.
- Do not present synthetic personas, automated scans, simulated tasks, or agent reasoning as research with disabled people.
- Preserve conflicting and minority evidence; do not average away a severe or reproducible barrier.
- Separate accessibility-service availability from discoverability, usability, and successful activation.
- Preserve source attribution and context during migration. Keep one canonical version of each guide and a useful redirect at retired paths.
- State uncertainties, evidence limits, and what would change the recommendation.
