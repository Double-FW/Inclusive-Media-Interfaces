# Inclusive Media Interfaces

Accessibility and inclusive design for TV, streaming, playback controls, remotes, media access services, and relevant physical and connected product controls.

## Purpose

This repository focuses on how people discover, configure, navigate, and control audiovisual services and the products connected to those experiences. It covers both interface journeys and physical or connected control systems where they enable media access, independent use, and integration with assistive or environmental systems.

It is for product and UX designers, researchers, broadcasters, streaming providers, platform teams, engineers, assistive-technology specialists, and AI agents supporting their authorised work.

## Start here

1. Read [AGENTS.md](AGENTS.md) before using these materials in an AI-assisted workflow.
2. Identify the service, device, software version, task, access services, input methods, and environment.
3. Use the guide that owns the question:

| Need | Start with |
|---|---|
| Television setup, navigation, content discovery, remote use, access-service discovery, and spoken output | [Connected TV](Connected_TV.md) |

| Physical controls, environmental control, hardware integration, shared spaces, and connected-product ecosystems | [Physical and Connected Product Control](Physical_and_Connected_Product_Control.md) |

## Boundaries and related repositories

- [Inclusive Multimodal UX](https://github.com/Double-FW/Inclusive-Multimodal-UX) owns the general cross-platform framework for sensory/input/output modes and transitions. This repository applies it to media and connected product control.
- [Accessible Film, TV and Video Content Production Management](https://github.com/Double-FW/Accessible-Film-TV-and-Video-Content-Production-Management) owns accessible media planning and production.
- [Closed Caption Subtitles](https://github.com/Double-FW/Closed-Caption-Subtitles) owns caption and subtitle authoring and delivery. This repository covers how viewers discover and use those services in interfaces.
- [AVMSD delivery and evidence repository](https://github.com/Double-FW/The-Audiovisual-Media-Services-Directive-AVMSD-) owns regulatory routing and evidence. This repository does not determine legal applicability or compliance.
- [Inclusive Games Design](https://github.com/Double-FW/Inclusive-Games-Design) owns game-specific interaction and player experience.

## Evidence and limits

Guidance describes design aims and questions to evaluate. It does not establish that a product is accessible, tested, or legally conformant. Keep source-based claims, user research, technical inspection, inference, and untested recommendations distinct. Do not present synthetic personas, generated scenarios, or agent review as research with disabled people.
