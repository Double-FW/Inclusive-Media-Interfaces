# Inclusive Media Interfaces

Accessibility and inclusive design for TV, streaming, playback controls, remotes, and media access services.

## Purpose

This repository focuses on how people discover, configure, navigate, control, and watch or listen to audiovisual services. It treats media access as an interaction and service-design concern across devices and environments.

It is for product and UX designers, researchers, broadcasters, streaming providers, platform teams, engineers, accessibility specialists, and AI systems supporting their authorised work.

## Scope

Guidance may cover:

- setup, discovery, navigation, search, playback, and return journeys;
- television, streaming, and other media-player interfaces;
- remote controls and alternative input methods;
- playback state, focus, feedback, errors, interruption, and recovery;
- discovery and control of captions, subtitles, audio description, sign-language presentation, and other access services;
- user choice, preferences, persistence, and consistency across devices.

Evaluate the interaction as experienced in the intended product and environment. Media availability alone does not establish that a person can find, activate, understand, or control an access service.

## Boundaries and related repositories

- **Inclusive Multimodal UX** owns general cross-platform modality and semantic-structure guidance. This repository applies those ideas to audiovisual interfaces and links to the canonical source rather than repeating it.
- [Accessible Film, TV and Video Content Production Management](https://github.com/Double-FW/Accessible-Film-TV-and-Video-Content-Production-Management) owns planning and production of accessible media content and its hand-offs.
- [Closed Caption Subtitles](https://github.com/Double-FW/Closed-Caption-Subtitles) owns caption and subtitle authoring and delivery guidance. This repository focuses on how viewers discover and use those services in an interface.
- [AVMSD delivery and evidence repository](https://github.com/Double-FW/The-Audiovisual-Media-Services-Directive-AVMSD-) owns regulatory routing and evidence. This repository does not make legal applicability or compliance decisions.
- [Inclusive Games Design](https://github.com/Double-FW/Inclusive-Games-Design) owns game-specific interaction and player experience.

## Start here

1. Read [AGENTS.md](AGENTS.md) before using these materials in an AI-assisted workflow.
2. Define the service, device, media version, environment, and task being considered.
3. Trace how a person discovers, enables, configures, uses, and changes relevant controls or access services.
4. Check for equivalent routes, clear state and feedback, retained preferences, error recovery, and realistic use conditions.
5. Record the evidence, limitations, and next review or user-research action.
